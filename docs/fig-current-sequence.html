Neu.Tail — Sequence Diagram, Current Implementation

One session, as the code runs it today — plus a planned ResponseComposer

Not a blueprint reproduction (that's Fig. 02 — see docs/fig-02-as-built.html). This traces what the code actually does right now, in one continuous narrative: intent routing, PERSONA, MUSE's vector-search-backed discovery with the real evaluator loop, TAILOR fit, and CARE/SENTRY/CONCIERGE/TALLY upsell — then adds one thing that doesn't exist yet, greyed out on purpose.

Everything in solid color below is real and live-verified (see README.md / RUNBOOK.md for the evidence each line cites). The single grey, dashed block at the bottom — RESPONSECOMPOSER — is not built: today, orchestrator.classify_intent() returns exactly one intent (discovery | fit | service | unknown), and handle_message() is a plain if/elif chain — never a fan-out to more than one specialist per message. A ResponseComposer only becomes necessary once that changes: a compound request (e.g. "recommend something for date night and what's my loyalty balance") would dispatch PERSONA+MUSE and TALLY independently and in parallel, and something has to merge their two answers into one reply before it reaches the Orchestrator. That's drawn as a hypothetical, not a real path.
